# Deploying PayFlow (free tier)

```
Browser ──▶ payflow-web (Render static site, React) ──HTTPS──▶ payflow-api (Render, Docker, Spring Boot) ──▶ Neon PostgreSQL
                                                                     ▲
GitHub push to main ──▶ GitHub Actions: tests → Docker images → Render deploy hook
```

The provider dashboards change from time to time, so button names may differ slightly from this guide.

## What you need

- Your GitHub repo with PayFlow pushed (the Actions tab should show a green run)
- A **Neon** account (https://neon.tech) for a free PostgreSQL database that doesn't expire
- A **Render** account (https://render.com). Sign in with GitHub so it can see your repo
- *(Optional)* a Gmail account with an App password, if you want OTPs by real email

## 1. Create the database (Neon)

1. Create a project named `payflow` in the region closest to you (e.g. Singapore).
2. Open **Connection details** and note the **host**, **database**, **user** and **password**.
3. Build the JDBC URL: `jdbc:postgresql://<host>/<database>?sslmode=require`

## 2. Deploy both services with the Blueprint (recommended)

1. In Render: **New → Blueprint**, then pick your `payflow` repo. Render reads `render.yaml` and proposes two services:
   **payflow-api** and **payflow-web**.
2. Fill in the values it asks for:

| Service | Key | Value |
|---|---|---|
| payflow-api | `DB_URL` | the JDBC URL from step 1 |
| payflow-api | `DB_USER` / `DB_PASSWORD` | from Neon |
| payflow-api | `ADMIN_PASSWORD` | a strong password (12+ chars, letters and numbers) |
| payflow-api | `CORS_ORIGINS` | leave blank for now, then set it in step 4 |
| payflow-web | `VITE_API_URL` | leave blank for now, then set it in step 4 |

3. Click **Apply**. The first API build takes about 5–10 minutes.
4. Once both services have URLs (e.g. `https://payflow-api-xxxx.onrender.com` and `https://payflow-web-xxxx.onrender.com`):
   - payflow-api → Environment → `CORS_ORIGINS` = the **web** URL. Save; it redeploys.
   - payflow-web → Environment → `VITE_API_URL` = the **api** URL, with no trailing slash. Save, then **Manual Deploy → Clear build cache & deploy**,
     because Vite bakes this value in at build time.
5. Check:
   - `https://<api-url>/actuator/health` → `{"status":"UP"}`
   - Open the web URL: the sign-in page lists the **demo accounts** (because `DEMO_MODE=true`).

`JWT_SECRET` is generated by Render automatically. `DEMO_MODE` and `OTP_SANDBOX_SHOW_CODE` are already set to `true`,
so anyone can try the app straight away.

## 3. Continuous deployment

1. payflow-api → **Settings** → copy the **Deploy Hook** URL.
2. GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**:
   name `RENDER_DEPLOY_HOOK_URL`, value = the hook URL.
3. Push any commit to `main`: Actions runs the tests, publishes images and calls the hook, and Render redeploys the API.
   The Blueprint sets `autoDeploy: false` for the API, so **only commits that pass the tests are deployed**.

## 4. (Optional) Real OTP emails instead of on-screen codes

1. Turn on 2-Step Verification for your Google account, then create an **App password**
   (Google Account → Security → App passwords).
2. Add these to payflow-api:

```
OTP_DELIVERY=email
OTP_SANDBOX_SHOW_CODE=false
MAIL_FROM=PayFlow <you@gmail.com>
SPRING_MAIL_HOST=smtp.gmail.com
SPRING_MAIL_PORT=587
SPRING_MAIL_USERNAME=you@gmail.com
SPRING_MAIL_PASSWORD=<16-character app password>
```

Keep these values only in Render's environment settings, never in GitHub. With real email, demo
accounts can't receive codes (their addresses are fake), so set `DEMO_MODE=false` too.
For interviews, on-screen sandbox codes are usually the better choice.

## 5. Things to know about the free tier

- Free Render services **sleep after about 15 minutes** without traffic, and the first request then takes up to a minute.
  Open the link a minute before you share or demo it.
- The demo data is created once. To reset it, delete the tables in Neon (or create a new Neon branch) and redeploy.
- All environment variables are listed in `backend/src/main/resources/application.yml`, with defaults and comments.

## Manual setup (without the Blueprint)

- **Web Service:** Root directory `backend`, runtime Docker, health check `/actuator/health`, with the env vars above.
- **Static Site:** Root directory `frontend`, build `npm install && npm run build`, publish directory `dist`,
  env var `VITE_API_URL`, plus a **rewrite rule** from `/*` to `/index.html`, so public payment links (`/pay/...`) work.
